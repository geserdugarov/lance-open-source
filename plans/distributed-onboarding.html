02Keep each invariant with its owner

One owner for every guarantee.

Architecture & decisions ↗

SQL semantics belong to the engine. Scheduling belongs to the orchestrator. Lance owns row visibility, model/index validity and publication. Device backends execute bounded numerical operations.

SQL engine: decide what the query means.

Keep joins, SQL types, collations and transaction semantics in the engine. The adapter maps a supported scan/search request and keeps unsupported predicates local.

Useful seams already present

CommitHandler · ExternalManifestStore · ObjectStoreProvider · CompactionPlanner · native optimization plans · scalar plugin registry.

Coupling to address carefully

DataFusion component types still appear in core interfaces. Scalar plugins are version-coupled. The custom vector loader accepts a legacy reader. Use additive, current-format contracts where a real use case needs them.

03Distributed execution is a protocol

Compute can retry. Publication must reconcile.

Proposed records & algorithm ↗

Workers create immutable artifacts. A coordinator selects results, validates the intended job and publishes through Lance. Durable recovery state lives beyond an actor's memory.

PLANNED

Pin the source and persist the plan.

Bind table identity, incarnation, branch, manifest version, schema, fields and model parameters. Protect the source snapshot through the job and its recovery window.

Retry with a fresh artifact identity. Select one successful attempt. Keep unreferenced objects through the recovery window; a failed task may still have written data.

Proposed recovery requirements

One successful task result is not a committed dataset. Exactly-once visibility must be demonstrated per operation; retries are not exactly-once execution. See the failure matrix.

SQL & Ray design ↗

PostgreSQL-family path

FirstQualify the existing pglance baseline against one engine/Lance/Arrow combination.
ThenStatement-scoped snapshot reads, streaming, cancellation, safe types and pushdown.
LaterTransaction-wide external snapshots or coordinated writes need their own tested protocol.

Ray path

FirstMeasure existing reads, builds, compaction and vector search.
ThenDurable recovery, bounded fallback scans and compaction-aware work assignment.
MeasureWorker/native thread multiplication, queue time, driver candidates and concurrent-query lifecycle.
ANN is approximate. Sorting local candidate lists cannot recover missed neighbors. Oversampling and reranking need recall measurements against exact ground truth.
SQL compatibility has layers. A PostgreSQL-compatible dialect does not establish FDW ABI compatibility. Qualify the exact openGauss/GaussDB-family engine separately.

Candidate payload is approximately workers × local candidate limit × row width. Keep wide columns out of this exchange where possible. Separate FTS ranking, joins and aggregation from vector top-k semantics.

1. PipelineGenerate embeddings externally on NPU; write ordinary Lance vectors.

06Make the next upgrade easier

Keep product logic behind narrow contracts.

Cooperation & upgrade strategy ↗

Shared invariants and tests belong upstream. Engine adapters, device implementations and deployment policies can evolve in their own packages. Measure upgrade effort to find out whether the boundaries work.

Shared contributionLanceDB / community valueHuawei value
Provenance + recoveryReliable builders across schedulersFewer correctness patches
Bounded execution + metricsPredictable service behaviorSQL/Ray integration reuse
Optional compute contractsMore hardware choicesAscend backend isolation
Capability + conformance testsSafer releases and adaptersLess repeated upgrade work

Stable formats

Honor released backward/forward contracts. Preserve legacy read behavior and use historical fixtures.

Unstable revisions

Allow redesign. Do not add migrations or compatibility scaffolding for intermediate unstable formats.

Private extensions

Use tested adapters, reference implementations and an explicit patch ledger. Keep new functionality off legacy writers/loaders.

07Retire risk in dependency order

A plan with evidence at every gate.

Full backlog, owners & risks ↗

Indicative 22-week program with six engineering roles, available Ascend hardware and upstream review capacity. Dates are planning assumptions; experiments decide promotion.

P0 · Core lead + all owners · weeks 1–2

Reproduce before redesigning.

Confirm engine, workloads, deployment objectives and hardware. Pin stable/development matrices and inventory private patches.

  • Reproduce Ray data/search and a pglance scan.
  • Profile bottlenecks and measure current upgrade effort.
  • Exit: baseline reports and bounded first RFCs.
P1 · Storage/runtime + core · weeks 3–6

Make one operation recoverable.

Add a durable execution record around native plans. Validate identity, capabilities, attempts, coverage and publication outcome.

  • Enforce fencing and protect source/artifact retention.
  • Inject failures at each stage, including a lost commit reply.
  • Exit: known outcomes and rejected incompatible workers.
P2 · Ray engineer + core · weeks 5–10

Bound distributed work.

Improve existing Lance-Ray fallback scans, fragment grouping, cancellation and maintenance recovery.

  • Measure 1/2/4/8-worker scaling and driver growth.
  • Compare compaction-aware segment assignment policies.
  • Exit: memory, quality and recovery gates.
P3 · SQL engineer · weeks 7–12

Qualify the SQL boundary.

Modernize pglance, choose process isolation and establish snapshot, type and predicate guarantees.

  • Exercise streaming, rescans, cancellation and EXPLAIN.
  • Keep unsupported predicates local and writes separately scoped.
  • Exit: an explicit tested engine/feature matrix.
P4 · NPU engineer + core · weeks 9–16

Promote a kernel only after measuring.

Qualify the runtime, demonstrate an embedding pipeline, then test a bounded assignment/rerank prototype.

  • Validate numerical quality and CPU-readable artifacts.
  • Include conversion, transfers and memory in measurements.
  • Exit: useful end-to-end benefit or an explicit decision to stop.
P5 · Test/performance + all owners · weeks 17–22

Prove the integrated system can evolve.

Run soak/failure tests and a stable-release upgrade rehearsal. Package supported combinations and operating procedures.

  • Record remaining patches, adapter edits and engineer time.
  • Publish reproducible performance/quality reports.
  • Exit: conformance, known limits and upstream review outcomes.
Correctness dependency chain: P0 → P1 → P2 → P5. P3/P4 also join P5; P4 finishes in week 16 and controls P5’s week-17 start.
Decision gates, not promised numbers. Proposed initial gates include a measured NPU gain ≥1.5× at equal quality, CPU regression tolerance of 5% after variance checks, and recall at least 0.5 plus the stricter workload target. Published Lance-Ray surface

Requires a running Ray cluster, matching packages and a shared dataset with 768-dimensional vectors. Application environment variables choose the source version.

import os
import lance
import lance_ray as lr
import numpy as np
import ray

ray.init(address="auto")
snapshot = lance.dataset(
    os.environ["LANCE_DATASET_URI"],
    version=int(os.environ["LANCE_DATASET_VERSION"]),
)
result = lr.vector_search(
    uri=snapshot,
    nearest={"column": "vector", "q": np.full(768, 0.01, dtype=np.float32), "k": 10},
    columns=["id"],
    num_workers=2,
    include_unindexed=True,
)

This uses existing distributed search. It does not establish recall or memory bounds; the current flat fallback still needs attention. Pinned source evidence →

09Your first contribution

Find the invariant. Choose its owner.

Documentation index ↗

A new backend should add an implementation and conformance cases. A new scheduler should reuse storage semantics. A release upgrade should reveal a bounded adapter change.

Working vocabulary

Snapshot / manifest version

An immutable dataset view. Its number is meaningful only with the table, incarnation and branch; retaining a version requires an actual cleanup/retention policy.

Fragment vs physical index segment

A fragment identifies dataset data. An index segment is a physical search artifact covering fragments; several segments can implement one logical index name.

Attempt vs operation

An operation is durable logical intent. A task can run several attempts; each attempt needs distinct output identity, and only selected outputs can be published.

Direct commit vs physical merge

Direct commit can retain separate models in separate segments. Physical merge combines storage and requires stricter model/layout compatibility.

Stable format vs plugin interface

Stable persistent bytes are a compatibility contract. A Rust extension interface can still require source updates and recompilation; the scalar registry currently documents that requirement.

Contributor starting sequence

  1. Read the current-state audit and exact evidence pins.
  2. Reproduce the gap on the selected release combination.
  3. Locate the owning module in ARCHITECTURE.md.
  4. Refresh related issues and inspect overlapping PRs.
  5. Propose the smallest contract change with a concrete consumer.
  6. Add tests at the invariant owner, then connector conformance.
  7. Record format effects, fallback behavior and upgrade impact.

Follow repository and language guides. Keep local unit fixtures small, use historical stable fixtures for compatibility, and require recall assertions for vector behavior.
