The key finding: the v12 “distributed cache” is a per-process RAM/SSD backend. It contains no router, actor coordinator or distributed ANN reducer. Selected prewarming does not constrain which partitions a query searches.

01 / Project boundaries

One clear owner for each responsibility

The local mechanism belongs beside its native codecs. Every decision involving multiple workers belongs in Lance-Ray.

Native engine

lance-open-source

Store, load and search correctly

  • RAM/SSD backend and bounded eviction
  • Codecs, scopes, integrity and invalidation
  • Strict warmup and current IVF_RQ layouts
  • Native query planning and final reduction
  • Thin Python bindings; no Ray dependency
Distributed service

lance-ray-open-source

Decide where and when work runs

  • Long-lived actors and local Sessions
  • Assignments, replicas and readiness
  • Query routing, bounded dispatch and retries
  • Pinned snapshots, rollout and drain
  • Recovery and service-level observability
Unchanged runtime

ray-open-source

Execute through existing public APIs

  • Actor processes and task scheduling
  • RPC and immutable result transport
  • Public placement and resource controls
  • Existing process and node fault reporting
  • No connector, scheduler or GCS changes

03 / Adapting the native cache

Port the contracts, preserve the newer engine

The current Lance branch already has backend configuration, detailed diagnostics and richer IVF_RQ caching paths.

Local persistence stays in Lance

Payload RAM→Local SSD→Source loader
  • Separate index-state RAM, optional payload RAM and dataset/file metadata budgets.
  • One live backend locks each directory. Publish through temporary files and atomic rename; validate integrity on reads.
  • Reserve disk capacity before writing. Count temporary files and failed deletions; evict locally with bounded LRU.
  • Ordinary queries can bypass failed SSD persistence. Strict prewarming reports the failure.
  • Fenced invalidation prevents a slow loader from restoring retired entries.

Current IVF_RQ needs more than whole partitions

  • PartitionEntry.*: existing whole-partition codecs.
  • rq.partition-codes: encoded payloads whose resident rows are reattached by Lance.
  • rabit.plane: sign/extended plane entries with priority and row-gather behavior.
  • Keep no-promotion, tier-probe and partial-read contracts. Weigh decoded memory separately from serialized disk bytes.
  • Index metadata, live handles and legacy paths retain their existing memory/read behavior.

Use Session(index_cache_backend=...) with a proposed tiered backend. Extend existing cache_diagnostics(); avoid a competing v12 configuration/statistics API.

Warmup has a precise promise: every selected payload is persisted together at a successful completion checkpoint. Eviction can happen later. An empty assignment means no work; “all partitions” must be explicit.
04 / Query correctness

Sharding needs native semantic seams

Lance-Ray dispatches work. Lance decides what that work means and how its results form one valid query result.

Proposed primitiveLance ownsLance-Ray owns
plan_vector_querySnapshot validation, per-segment models, ordered probes, candidate budgetsGroup work by assignment and ready replicas
search_vector_partitionsSearch exact segment/partition scope; emit candidates and explicit work completionDispatch, concurrency limits, deadlines and retry attempts
finish_vector_queryCompleteness, native ranking, deduplication, refinement and projectionCollect bounded results and call the reducer on a selected actor
Identity

A partition belongs to a segment

Route by physical segment UUID + partition ID. S0/4 and S1/4 can have different centroids. Keep dataset snapshot, routing epoch and cache generation separate.

Completeness

An empty result is still work

Every selected work item must acknowledge completion. Accept one attempt per item, reject wrong snapshots, and retry or fail when coverage is missing.

Candidate budget

Global refinement happens once

For k=10 and refine factor=4, up to 40 candidates per selected partition may be needed. Four partitions can transfer 160, before native global reduction and refinement.

Query shapeReplicated modeInitial partitioned mode
Fixed probes, supported flat IVF, complete coverageComplete native queryShard after native parity gate; exact refinement after finalizer validation
Adaptive probes, HNSW, filters, multivectors, advanced batchesComplete native queryObservable full-native fallback, or configured unsupported error
Unindexed fragments or newer overlaysNative delta/overlay reconciliationFull-native fallback preserving the same snapshot
A shard response is missingRetry the complete read within deadlineRetry, discard partial work and run a complete native query, or fail

Do not concatenate fragment-local ANN outputs, treat index_segments as partition selection, silently enable fast_search, or drop unsupported query options. Existing Ray Data Lance reads are not a global ANN reducer.

05 / Lifecycle and recovery

Warm, publish, drain

Serve one pinned snapshot per query. New assignments become visible only after their workers prove readiness.

01Resolve V+1

Read the committed snapshot and physical segment identities.

02Prepare workers

Open Sessions and reuse compatible immutable payloads.

03Warm and verify

Strict persistence checkpoint, expected snapshot and capability handshake.

04Publish epoch

New requests use V+1. In-flight V requests keep V.

05Drain and release

Reclaim retired cache entries after their last served snapshot drains.

Process restart

Reuse the same local SSD

Keep worker paths outside Ray temporary directories. Reacquire the exclusive lock, rebuild state and recheck readiness. RAM is cold.

Node loss

Use a replica or reload

A different node does not inherit the lost node's SSD. Serve another ready copy or rebuild from canonical storage. Verify replicas occupy different nodes.

Disk or controller failure

Keep the contract visible

Failed strict warmup cannot mark an assignment READY. Recover controller state from a durable descriptor; reconcile fencing tokens before routing resumes.

What unchanged Ray provides, and what the service must add

Use public actors, ObjectRefs, resource controls and scheduling strategies. The proposed default uses controller-managed worker replacement with automatic actor/task retries disabled, so there is one recovery policy. Soft node affinity can still wait for resources on a live node; Lance-Ray enforces startup deadlines.

Ray can restart a process but does not restore its application state. A named or detached actor is not a durable deployment record. Lance-Ray persists snapshot/assignment state, manages request deadlines, and makes warmup and retry handling idempotent.

Sources: Ray scheduling and actor fault tolerance; the local pinned source remains the implementation authority.

06 / Proposed usage

Local mechanisms, distributed configuration

These sketches show the intended interface. The tiered backend and serving API are not implemented in the current checkouts.

API sketches
Lance · no Ray required · proposed backend
from pathlib import Path
import lance
from lance.dataset import Session

root = Path("/mnt/nvme/lance-cache/local")
root.mkdir(parents=True, exist_ok=True)
session = Session(
    index_cache_backend={
        "kind": "tiered",
        "options": {
            "path": str(root),
            "index_metadata_l1_capacity_bytes":
                str(64 * 1024**2),
            "l1_partition_capacity_bytes":
                str(512 * 1024**2),
            "l2_capacity_bytes": str(8 * 1024**3),
        },
    },
    metadata_cache_size_bytes=64 * 1024**2,
)
ds = lance.dataset(
    "s3://example/vectors.lance",
    version=42, session=session,
)
# Existing diagnostic API, extended tier details:
stats = session.cache_diagnostics()
The native backend owns files, capacity, codecs and integrity. Session metadata has a separate budget. Existing memory-only Sessions keep their defaults.
Lance-Ray · proposed service facade
import ray
from lance_ray.serving import (
    CacheConfig, VectorSearchService,
)

ray.init(address="auto")
service = VectorSearchService.start(
    name="catalog-vectors",
    control_uri=
        "s3://example/service-state/catalog/",
    uri="s3://example/vectors.lance",
    version=42,
    index_name="embedding_idx",
    mode="replicated", workers=3,
    warmup="all",
    cache=CacheConfig(
        root="/mnt/nvme/lance-cache/catalog",
        index_metadata_l1_capacity_bytes=
            64 * 1024**2,
        l1_partition_capacity_bytes=
            512 * 1024**2,
        metadata_cache_size_bytes=64 * 1024**2,
        l2_capacity_bytes=8 * 1024**3,
    ),
)
service.wait_ready(timeout_s=120)
result = service.search(
    query_vector, k=10, nprobes=8,
    refine_factor=4, columns=["title"],
)
service.refresh(version=43)
service.close()
The caller supplies query_vector and durable deployment storage/configuration. Lance-Ray constructs independent Sessions and worker roots; no Ray connector changes are involved.
Strict selected warmup: proposed shape and empty-selection rule

Replicated warmup="all" requires the full selected payload set to fit on each worker's SSD. Explicit warmup="none" permits demand loading and claims no warm payloads at READY. Partitioned mode warms each worker's assignment. Do not silently shrink a requested set.

ds.prewarm_index_partitions(
    "embedding_idx",
    selections=[
        {"segment_id": segment_uuid, "partition_ids": [1, 4]},
    ],
)
# [] means no work; "all" explicitly selects every partition.
# This does not restrict subsequent ordinary queries to [1, 4].

Validate all selected IDs before payload work. Persist RAM hits as well as source loads. The selected set must fit simultaneously at completion; failure can leave a partial cache. Permanent assignment residency would require a separate lease design.

07 / Cost model

Estimate the tradeoff before benchmarking

These calculators illustrate capacity and a serial latency bound. They do not predict measured throughput or account for skew.

How many SSD copies?

Assume the complete eligible payload set is warmed. Replicated mode stores one full copy per worker. Balanced sharding stores one copy per partition replica.

PARTITIONED · TOTAL48 GiB12 GiB per worker on average

Actual provisioned space needs headroom for temporary writes, rollout overlap, skew, filesystem allocation and other processes. Warm checkpoints do not reserve these copies forever.

This model covers SSD payloads only. Native IVF_RQ resident row/factor stores can span a whole segment and be duplicated across actors even when its partitions are sharded. Budget them separately without double-counting bytes already charged to RAM caches.

What fraction can this cache accelerate?

If index-payload loading accounts for a fraction f of serial latency, removing that entire cost gives an ideal ceiling of 1 / (1 - f).

SSD still costs I/O and decoding. Raw-vector refinement, payload reads and computation remain. Distributed fan-out adds RPC and reduction. Test the whole production query, including recall.

08 / Delivery and review

Three gates, with a useful service at each stage

Local cache parity and distributed query parity are separate proof obligations.

Gate 1 · Lance

Current native cache

Port local persistence, bounded SSD, exact invalidation and strict warmup. Integrate current codecs, resident weights and diagnostics.

Evidence: hit/miss/restart, integrity, capacity, races and current IVF_RQ layout tests. Lance works without Ray.

Gate 2 · Lance-Ray

Replicated serving

Actor-local Sessions, pinned snapshots, readiness, placement, recovery and refresh. Every request is one complete native query.

Evidence: exact-wheel compatibility, multi-fragment query parity, same-node and node-loss recovery, full-query benchmarks.

Gate 3 · Both projects

Partitioned serving

Native plan/search/finish primitives plus Lance-Ray dispatch, completeness checks, attempt deduplication and explicit fallback.

Evidence: multi-segment candidate/refinement parity, duplicate and missing replies, failure during rollout, recall and RPC costs.
